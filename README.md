# シカクメイシ Webヒアリング

20種類のデザインを「顧客の好みを把握する見本」として比較するWeb画面です。完成サイトのテンプレート選択や自由編集ビルダーではありません。ユーザーの屋号・氏名・資格・見出し・紹介文・ロゴ・写真を、同じデータで全見本に反映します。

## 文章・ロゴ・配色の一括反映

「デザインの好み」で情報を入力し、ロゴやプロフィール写真を選ぶと、20個のHTML見本が同じ内容で更新されます。見本一覧の上部にある「好きな色合いで、見比べる。」には、提供資料 `チートシート_配色.png` の20配色を資料の順番で掲載しています。スウォッチは背景・メイン・アクセントの順です。

初期設定はブルー系の「05 ネイビー×エレクトリック」（背景 `#F4F7FD`、メイン `#173A8A`、アクセント `#4B7CF5`）です。「元の配色」という選択肢はありません。旧保存データの未指定・元の配色はブルー系に、旧グリーンは北欧セージ、旧ベージュはラテ＆クレイ、旧モノトーンはミニマル・オフホワイトに引き継ぎます。

背景・見出し・ボタンには資料の3色をそのまま使用し、装飾面・グラデーション・陰影にはそこから作った補助色を使います。ボタン上の文字は読みやすさに応じて明暗を切り替えます。ダーク配色も背景・カードを暗色に統一します。ガラスの透明感や立体の陰影、黒い罫線などの特徴は維持します。ロゴ・人物画像のファイル自体は変更しません。写真のモノクロ表現など、各デザイン固有の見せ方は引き続き適用されます。

一覧・拡大・スマホ・好きな見本の比較は共通データを参照します。あとから読み込む見本や絞り込み後の見本にも現在の配色が反映されます。選択はこのブラウザに保存され、確認画面とJSONの `designPreferences.palette` / `paletteName` に引き継がれます。配色を変更しても文章の承認は解除しません。最終確認のチェックは再確認のため解除します。

JSONには配色ID・名称に加え、`designPreferences.paletteColors` に資料の3色を記録します。制作用の `?reference=1` 元画像比較プレビューは顧客用の配色選択とは別のもので、保存した文章・画像・配色を適用しません。

## GitHub Pagesでの公開

公開URL：<https://michiocorporation.github.io/sikakumeisi/>

GitHub Pagesは `main` ブランチのルートを公開元として使用します。ルートの `index.html` から `dist/` のWebヒアリング画面へ自動的に移動します。URLのクエリとページ内リンクも引き継ぎます。`.nojekyll` により、HTML・JavaScript・画像をJekyllで加工せず配信します。

更新時は、このリポジトリの `dist/` と必要な生成元を更新して `main` にpushしてください。見本を再生成する場合は `node scripts/generate-previews.mjs`、確認は `node --test tests/model.test.mjs` です。公開URLはそのまま使えます。

## 起動

`プレビューを起動.cmd` をダブルクリックするか、Node.jsで `node scripts/serve.mjs` を実行し、表示されたローカルURLを開きます。外部パッケージのインストールは不要です。

`dist/index.html` を直接開くこともできますが、ブラウザの file URL に対する保存制限があるため、ローカルサーバーまたはHTTPS配信を推奨します。

## 構成

### 添付19種類の再構成（2026-10-14）

19種類の追加参考画像を基準に、見出し、人物、カード、ボタン、装飾の位置と大きさを個別に再構成しました。全20種類のデスクトップ見本を1672×941に統一し、一覧でも画像全体を同じ比率で比較できます。スマートフォンでは文章・人物・カードの順に並べ直します。

`dist/design-review.html` は全20種類の制作確認用画面です。「HTML」「参考画像」「重ねて確認」と20種類の一覧を切り替えられます。重ね合わせでは画像の濃さを調節できます。この画面はヒアリング入力を変更しません。お客様の文章・画像・選択色の反映は通常のヒアリング画面で確認してください。

主な文字・カード・ボタン・アイコンはHTML/SVGで描画しています。通常の人物には提供済みの元人物写真を輪郭で切り抜いて配置し、ピクセルアートには専用の人物を使用しています。光・水彩・紙・街並みなどの細部は、参考画像から文字・カード・人物の領域を除いた背景部分も組み合わせています。配色選択時は、その背景部分にも同じ配色を使った階調変換を適用します。細かな手書き文字、図形、写真の比率には参考画像との差があります。

長いプロフィールは小さいカード内で省略表示し、下部のプロフィール欄で全文を確認できます。お客様の情報が入力されている場合は、見本の追加資格や実績数値を非表示にします。

- `scripts/reference-layouts.mjs`：19種類の座標・文面・写真配置。
- `scripts/reference-designs.mjs`：19種類のHTMLと入力可能な部品。
- `scripts/reference-backgrounds.mjs` / `reference-atmosphere.mjs`：固有の図形・背景の質感と領域分離。
- `scripts/clean-portrait.json` / `portrait-paths.json`：人物を切り抜くSVGの輪郭。
- `dist/reference.css` / `reference.js`：19種類の専用スタイル、文字の収まり、スマホ表示、写真差し替え。
- `dist/assets/references/`：提供された参考画像。外部画像サービスへ接続しません。

### フラットデザインの再現版（更新）

`dist/flat-review.html` で制作HTML・元画像・半透明の重ね合わせを切り替えられます。元画像の1672×941の比率を維持し、閲覧サイズに合わせて縮小します。

フラットデザインだけを `scripts/flat-design.mjs` と `dist/flat.css` / `dist/flat.js` に分離しました。ヘッダー、カード、文面、ボタン、装飾面、アイコンを独立したHTML/SVGで構築しています。人物は顔やポーズが変わらないよう元画像をSVGの輪郭で切り抜いて使用し、ロゴは提供された画像を使っています。画面全体を1枚の画像にしてはいません。入力された屋号はロゴの見出しに代わって実際の文字として描画されます。

`?reference=1` は保存された入力を使わず元画像の見本文字を表示します。通常のプレビューでは従来どおり入力内容を反映します。名前や屋号を入力したら、元画像にある追加の架空資格は非表示にします。

日本語フォントはNoto Sans JPを同梱し、外部フォント配信への接続を不要にしています。利用条件は `dist/assets/NotoSansJP-LICENSE.txt` を参照してください。手書き文字・アイコン・人物の細い輪郭には元画像との差があります。

- `dist/index.html`：4ステップのヒアリング画面。今回の確認対象であるデザイン選択から開始します。
- `dist/app.js` / `app.css`：入力・画像処理・好み・比較・確認・JSON出力。
- `dist/model.js`：文章案、承認状態、入力検証、データ変換。
- `dist/catalog.js`：20種類の名称、分類、説明。
- `dist/palettes.js` / `palette.css`：配色チートシート20種類の色コード、初期設定と各デザインへの反映。
- `dist/previews/*.html`：デザインごとに独立した20個のHTML。個別に開けます。
- `dist/reference.css`：19種類の新しいスタイル。`preview.css` は旧版の保管用で、現在の見本では読み込みません。
- `dist/preview.js`：入力内容を安全に `textContent` と画像へ反映。
- `scripts/generate-previews.mjs`：各HTMLの生成元。変更後は `node scripts/generate-previews.mjs`。

個別HTMLはまとめて20種類作成済みです。今後は1種類ずつ調整できます。入力反映・画像検証・共通部品は一元管理することで、20個の同期処理を別々に保守する必要がありません。生成されたHTMLを直接編集した場合、再生成で上書きされるため、継続的な変更は生成元にも反映してください。

## 使用範囲と保存

- 「好き」は3つまで、「避けたい」は複数可。「好きな理由」と「お任せ」も記録します。
- 画像はPNG/JPEG/WebP、5MB以下。ブラウザ内で最大辺1200pxに縮小し、WebPで保存します。SVGは受け付けません。
- 入力は同一ブラウザのlocalStorageに保存。別端末との同期、制作側への送信、サーバー保存は未接続です。
- 「使い方」から保存内容を削除できます。共有端末での個人情報の保持にご注意ください。
- JSONには入力情報、素材画像、文章状態、好み、未確認項目が含まれます。ダウンロードを送信完了としては表示しません。
- 初期サンプルの文章・写真は確定情報として出力しません。
- 自己紹介・業務紹介・大切にしていることを承認できます。文章や依存する材料の変更で承認を解除します。
- 見出し・紹介文の手入力欄はプレビュー用の材料です。最終原稿として制作側で確認してください。

## 文章機能

文章案は入力情報から決まった文型で組み立てる試作機能です。AI APIの接続は行っていません。経歴・実績・資格・数字・料金・業務は補完しません。承認済み原稿を制作側に渡すための状態管理まで実装しています。本運用ではAI生成用のサーバーAPIと保存・引継ぎ先の接続が必要です。

## 元資料との関係

チートシートおよび各サンプル画像を参考にHTML/CSSとして再構成しました。元画像の画素単位の複製ではありません。画像に焼き込まれた文字や文字化けを流用せず、日本語はUTF-8のDOMテキストです。人物サンプルとブランドロゴは、同プロジェクトの提供素材を使用しています。

## 検証

`npm test`（または `node --test tests/model.test.mjs`）で空欄・事実の非補完・承認解除・完了条件・連絡先検証・データ反映・20個のHTML・20配色の色コード・初期値と旧保存データの移行・主要な文字と背景のコントラストを確認します。

本画面はヒアリング体験の試作です。顧客向けの本番受付として運用する際は、申込管理・安全なサーバー保存・制作担当への引継ぎ・アクセス制御・AI接続を追加してください。
